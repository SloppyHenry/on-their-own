# Statusbericht AP09 – Speichern, Laden, Export, Statistik

Stand: 11.10.2026 · Branch `ap/09-spielstaende` · Freigabe zum Zusammenführen: **offen**

## Geliefert
- **Spielstände** (`backend/simulacra/saves/`, Beschreibung in [spielstaende.md](../spielstaende.md)): Ein Stand ist eine konsistente Kopie der SQLite-Datei (Backup-API, ohne Journaldatei) plus Metadaten in `data/saves/index.db` (Name, Beschreibung, Sim-Zeit, Echtzeit, Schema-Version, Modell, Größe, Prüfsumme). Arten: manuell, Autosave, Sicherung, Import. Gleicher Name ohne ausdrückliche Bestätigung überschreibt nichts (Standard: neuer Stand).
- **Laden** mit Bestätigung: Prüfsumme und Integritätscheck, danach automatische Sicherung „Vor dem Laden – …“, Datei kopieren, Simulation neu aufbauen, Ereignis `simulation.loaded` → alle Browser bekommen einen frischen Snapshot. Das Modell steht im Stand (`meta.llm_model`); Laden verwendet immer das gespeicherte Modell (Entscheidung 10).
- **Autosave** nach N Sim-Stunden **oder** M Echtzeitminuten, Ringpuffer; löscht nie manuelle Stände oder Sicherungen. Dafür drei neue Parameter (`sim.autosave_sim_hours` 6, `sim.autosave_real_minutes` 30, `sim.autosave_keep` 5, jeweils mit Wirkungstest; Registry jetzt 76 Parameter, [parameter.md](../parameter.md) neu erzeugt).
- **Zurücksetzen** sichert vorher als „Vor dem Zurücksetzen – …“; Wahl „aktuelle Profile behalten“ oder komplett Standard. Parameter und eigene Presets bleiben erhalten (agentenbezogene Werte nur mit behaltenen Profilen).
- **Export/Import:** ZIP mit genau `state.db` und `manifest.json`. Import prüft Struktur, Größe, Prüfsumme, Schema-Version ≤ aktuell, SQLite-Integrität und lehnt jede Tabelle, Sicht oder jeden Trigger ab, die das frische Schema nicht kennt. Er legt immer einen **neuen** Stand an, nie den Live-Stand.
- **Statistik** (`stats/queries.py`, `GET /api/stats`): reine SQL-Abfragen auf Ereignissen und Protokolltabellen; dazu stündliche Stichproben (`stats_samples`, Migration 009) für Bedürfnis-, Stimmungs- und Beziehungsverläufe. Gesamt oder je Agent, Zeitraum Alles/Heute/Letzte 6 Std.
- **Ereignisverlauf** (`GET /api/events` mit `from_minute`, `to_minute`, `q`; `GET /api/events/export?format=csv|json`).
- **Oberfläche:** Spielstände-Dialog, Ansicht „Verlauf“ (Filter, CSV/JSON), Ansicht „Statistik“ (Kennzahlen, Tabellen, eigene SVG-Linien und Balken), Zurücksetzen-Dialog mit Profilwahl. Bilder: [Spielstände](img/ap09-spielstaende.png), [Verlauf](img/ap09-verlauf.png), [Statistik](img/ap09-statistik.png).
- Neue Ereignisse `simulation.saved`, `simulation.loaded` (Modelle, Beschreibung im Verlauf, WebSocket-Resync).

## Abweichungen und Grenzen
- **Kein Rückspulen** (laut Spezifikation optional): Laden eines Autosaves ist das echte Zurückspringen.
- **Laden und Zurücksetzen erzeugen zusätzlich Sicherungs-Einträge** („Vor dem Laden …“); sie zählen nicht zum Autosave-Ring und werden nicht automatisch gelöscht.
- Spielstände gibt es **nur bei einer Datei-Datenbank** (nicht bei `:memory:` in Tests).
- Das Modell wird im Stand in `meta.llm_model` gespeichert, nicht im Manifest allein.
- **Import legt immer einen neuen Stand an**, auch bei gleichem Namen (der Name wird eindeutig gemacht).
- Drei zusätzliche Parameter für den Autosave (nicht in der Spezifikation namentlich genannt, aber dort als „Parameter“ vorgesehen).
- Kopfzeile wurde für die neuen Knöpfe verändert (siehe oben); die Optik insgesamt bleibt zurückgestellt.
